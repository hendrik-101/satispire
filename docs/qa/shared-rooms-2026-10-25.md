## Delivered behavior

The home page opens the recent-room dialog. Room entries show output names and
rates; a direct room link bypasses the dialog. New-room creation navigates through
the client router to the same canonical URL used by Share, preserving the private
creator membership even when storage is blocked. Complete room plans and unlocks
use Convex transactions and live subscriptions. History is paginated and immutable;
undo appends a validated compensating edit, preserving unrelated later changes.

## Decisions and remaining limits

- Work used a new feature branch in the dedicated managed checkout. Routing and
  workspace integration were committed together because they share the new
  workspace interface; the offline `/local` route preserves local planning,
  file export and local WebMCP regressions. Shared mode never exposes a fake local
  room through WebMCP.
- The public `CONVEX_URL` runtime configuration keeps the immutable image reusable;
  it never contains a deployment/admin credential. Plans and history remain in
  Convex, not the Node listener or browser storage.
- Local drafts retain their original revision and require explicit replacement
  after a conflicting remote edit. Undo operates on atomic plan fields, so it can
  reject dependent/overlapping edits rather than guessing a merge.
- Membership is private browser storage with an in-memory fallback. When all
  storage is disabled, owner authority survives client navigation but cannot
  survive a full browser reload; the preserved share link still grants editor
  access. Recent rooms are browser-local, limited to 30, not a cross-device account.
- Recent-label refresh may restore authorized membership using a previously
  stored reusable room link if its private membership is missing. This can add an
  anonymous membership record; it cannot grant owner authority.
- No live Convex backend, credentials, infrastructure, merge or deployment was
  provisioned. Hosted transport/persistence acceptance remains a separate step
  against the configured backend; local verification is not a substitute.
- The initially deferred missing-configuration navigation was fixed during the
  PR follow-up: both the entry dialog and direct-room error screen now offer
  **Lokal weiterplanen**, leading explicitly to `/local`. Browser regressions
  verify that the action reaches the usable offline workspace. A delayed/batched
  server-acknowledgement test also protects the existing latest-plan editor
  behavior; it passes without changing save semantics.

## Hosted review follow-up: preserved drafts

The hosted Codex code review on `87e9e7f` identified one P2 issue: an unsubmitted
target draft became stale after the same participant saved a row or variant
change. Both flows were reproduced with failing browser regressions.

The workspace now receives the acknowledged room snapshot from its edit callback.
It advances a preserved draft's revision only for an independent layout edit,
when the draft previously matched the edit's base, the returned revision is at
most that one local increment, and the returned complete plan exactly matches the
submitted plan. An explicit render update clears the obsolete conflict notice.
A concurrent foreign update or an already-stale draft never gains a fresh base
through this path. All 16 focused room browser tests passed, including separate
rows/variant cases and safeguards for concurrent and earlier collaborator edits.

Final follow-up checks on production-code commit `2b32e31`: the production HTTP
smoke passed and all 84 Chromium tests passed against the compiled server. This
includes the four draft/rebase regressions and the unchanged offline workspace.
