# Fixed Vanilla snapshot

Every workspace uses `vanilla-1.0-tools-a1eb2fef-v1`, a bundled numeric Satisfactory 1.0 snapshot. There is no browser game-data import, runtime catalog editor or game installation dependency. Plan JSON contains the version and production intent, including the technology profile; importing a different catalog version fails atomically.

Source: [greeny/SatisfactoryTools data1.0.json at a1eb2fef1d5293baa5cd33ae88d08032600c6996](https://github.com/greeny/SatisfactoryTools/blob/a1eb2fef1d5293baa5cd33ae88d08032600c6996/data/data1.0.json). Source bytes SHA256: `4caf63ba1cfd495eb33534fd5d1ae92631e786e72ad833e39357cb5194faa35f`. [MIT notice](SatisfactoryTools-LICENSE.txt) is retained. The source's restricted artwork directories are not used. No icons, meshes, textures, item descriptions or raw game export are included. Names and numeric recipe facts are normalized into the existing catalog contract; floats from the source are converted using decimal spelling into reduced rational quantities. Upstream provenance is retained as `unverified-game`; metadata validation does not authenticate game facts.

The snapshot contains 175 item records, 11 actual production machine identities and 276 manufacturing recipe records. Internal `Mk1` class names do not create fictional user-facing machine tiers. The upstream snapshot omits converter recipes and some event content. Multi-output recipes are retained as catalog facts, but the current exact DAG solver rejects coproducts and cycles. The UI offers targets with a solvable standard chain under the applied profile. Explicit unsupported choices fail without replacing the previous plan. Oil loops, extraction/node-purity models and general linear optimization remain outside this first workflow.

HUB unlock tiers derive from tutorial/milestone schematics, excluding MAM and alternate schematics. The upstream snapshot lacks starting-recipe unlock links for Iron Ingot, Iron Plate and Iron Rod; the three explicit Tier 0 corrections identify `Schematic_StartingRecipes_C`. Research recipes without a HUB tier and alternates require explicit recipe checkboxes. HUB shortcuts select machines, recipes and transport tiers; the individual lists allow a narrower or custom unlocked profile. This is an explicit planning profile, not an inferred save state.

Belts have capacities 60/120/270/480/780/1200 items/min; pipes 300/600 m³/min. The shared solver enforces available machines and selected recipe unlocks for every reachable stage. It increases machine count and reduces utilization when a single per-item machine connection cannot accept the full-clock flow on the selected tier. All quantities remain rational. `Perfect Ratio` rejects a full-clock/transport conflict instead of promising full utilization. The layout sizes aggregate supply line counts with these same capacities.

# Geometry evidence

The pinned numeric source records zero production-machine dimensions and supplies no port coordinates. Public geometry sources disagree about release, visible footprint and clearance; none checked here establishes exact port coordinates for the pinned 1.0 release. The block projection therefore keeps `physicalFootprint` and `physicalPorts` null. It is a schematic in logical units, not a physical construction certificate. No guessed game measurement is introduced. Every floor has the same origin and area, automatic or selected row allocation, machine/manifold blocks and east-facing aggregate lift connections. No individual conveyor routing, machine height or height-fit calculation is included in this workspace MVP. Verified 2D geometry is still required before claiming a physically usable floorplan.
