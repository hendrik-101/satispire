# First planning slice

The authorized direction is a pure TypeScript domain, TanStack Start for the web workspace, and Convex for transactional collaboration. The first executable slice is the planner CLI and shared commands. UI implementation waits for the approved ImageGen reference in issue #5; no reference is present in this checkout or issues 1–12. Convex hosting and credentials are not assumed.

Production uses normalized exact rational strings (integers, decimals, or fractions) and explicit recipe choices. The initial solver supports acyclic, single-output recipes, shared dependencies, multiple targets and explicitly imported raw inputs. Cycles and coproduct recipes return diagnostics; automatic recipe optimization, energy estimates, amplification and game modifiers are unsupported rather than silently approximated. Separate clocking functions accept explicit versioned limits and per-machine shard allocations; these are not yet effective game rules or integrated graph clocking. Whole-chain stage scaling and a minimal rational nondecreasing Perfect Ratio operation recalculate all supported targets. Machine counts round upward; utilization stays exact.

Geometry is independently versioned and provenance tagged. Synthetic machine dimensions are examples in logical grid units, never Satisfactory measurements. Unknown or unverified game geometry cannot become layout-ready. Blocks are generated from counts and rows, including uneven arrangements, cardinal I/O and manifold topology. Stories share one footprint with reserved continuous lift corridors. There is no individual belt routing.

UI, classic MCP and WebMCP call the same validated application functions. Classic MCP uses stdio; WebMCP uses feature detection of document.modelContext. Tools carry explicit room context and use a server-bound participant capability, never a role supplied by a tool caller. Mutations check permission, expected revision and command ID atomically; retries do not double apply. Local memory is only a test/CLI adapter, not an online collaboration service.

Anonymous membership and invite tokens are bearer capabilities. Production transport must protect and hash these; no secrets appear in URLs/logs beyond intentional invitation links. Eight participants, stale edits, cross-room access and duplicate commands are test cases. Presence is scoped to view and floor; presenter following is opt-in and cancellable. These contracts must precede online exposure.

## Implementation sequence

1. Pin runtime/toolchain, write failing domain tests, implement exact numbers and validate a versioned synthetic catalog.
2. Solve selected production graphs and generate machineblock/multistory layouts with independent fixtures and deterministic tests.
3. Introduce role/revision/idempotency commands, actual classic MCP calls and feature-detected WebMCP with shared errors and authorization tests.
4. Provide a runnable JSON CLI, reproducible build and CI. Review the immutable candidate while the PR stays Draft; no CodeRabbit during Draft and no merge without the parent thread's integration decision.
5. After the selected design and a verified Convex deployment are available, connect the real workspace and online collaboration. Do not declare the complete web MVP delivered by a core-only slice.
